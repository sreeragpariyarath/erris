# Release Process

Erris release automation is intentionally staged. This document describes the
current foundation and the rules for future publishing.

## Current State

The repository uses Changesets for package version planning.

Available commands:

```sh
corepack pnpm changeset
corepack pnpm changeset:status
corepack pnpm version:packages
```

No command in the current repository publishes to npm.

## Changeset Rules

Add a changeset when a commit changes published package behavior, public API,
runtime behavior, generated declarations, package exports, or package
dependencies.

Do not add a changeset for:

- Documentation-only changes
- Test-only changes
- CI-only changes
- Internal scripts that do not affect package output
- Pre-release repository policy changes

Version files and changelog updates should be generated by Changesets, not
handwritten.

## Versioning

Versions begin in `0.x` while the API is experimental.

Expected flow:

1. Merge feature and fix commits with changesets.
2. Run the full verification suite.
3. Generate a version update with `corepack pnpm version:packages`.
4. Review package versions, changelogs, and lockfile changes.
5. Merge the reviewed version commit.

## Publishing

Publishing is deferred until a protected release workflow exists.

Future publishing must:

- Run only from reviewed commits on `main`
- Use npm trusted publishing through OIDC
- Publish with provenance
- Avoid long-lived npm write tokens
- Verify exact packed artifacts before publish
- Use a protected GitHub environment with explicit approval
- Verify registry metadata after publish

Local npm publishing is not allowed.
