# Release Process

Erris release automation is intentionally staged. The current repository can
track package changes and open version pull requests, but it does not publish to
npm yet.

## Overview

```text
Package-affecting PR with changeset
  -> merge to main
  -> release workflow runs checks
  -> Changesets opens or updates "version: release packages" PR
  -> maintainer reviews generated versions and changelogs
```

Publishing is a later, separate step after the npm `@erris` scope and trusted
publishing configuration are ready.

## Available Commands

- `corepack pnpm changeset`: Interactive prompt to declare package version
  bumps.
- `corepack pnpm changeset:status`: Check pending changesets against `main`.
- `corepack pnpm changeset:check`: Enforce changeset policy in CI.
- `corepack pnpm version:packages`: Consume changesets and update package
  versions and changelogs.

There is intentionally no local publish command.

## Changeset Rules

Add a changeset when a commit changes published package behavior, public API,
runtime behavior, generated declarations, package exports, or package
dependencies.

Do not add a changeset for:

- Documentation-only changes
- Test-only changes
- CI-only changes
- Internal scripts that do not affect package output
- Pre-release repository policy changes

Version files and changelog updates should be generated by Changesets, not
handwritten.

## Version Pull Request Workflow

The release workflow is defined in `.github/workflows/release.yml`.

Current behavior:

1. Runs on pushes to `main`.
2. Installs dependencies from the lockfile.
3. Runs `corepack pnpm check`.
4. Uses `changesets/action` to open or update a pull request titled
   `version: release packages` when pending changesets exist.

Current workflow permissions:

- `contents: write`
- `pull-requests: write`

The current workflow does not request `id-token: write`, does not publish to
npm, and does not create GitHub releases.

## Future Trusted Publishing

Publishing must be added in a separate reviewed commit.

Future publishing must:

- Run only from reviewed commits on `main`
- Use npm trusted publishing through OIDC
- Publish with provenance
- Avoid long-lived npm write tokens
- Verify exact packed artifacts before publish
- Use a protected GitHub environment with explicit approval
- Verify registry metadata after publish

The expected npm trusted publisher settings will be:

- Organization or user: `sreeragpariyarath`
- Repository: `erris`
- Workflow name: `release.yml`
- Environment: a protected environment such as `npm`

Local npm publishing is not allowed.
